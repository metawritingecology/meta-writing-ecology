# Source Use Guide

- **Status:** Public Repository Guide
- **Document type:** Source-routing and citation-use guide
- **Context:** Meta-Writing Ecology public GitHub surface
- **Authority boundary:** This guide does not establish citation style, source validity, Registry status, formal relation status, or semantic supersession.

## Purpose

This guide routes public-source use across repository files, OSF-linked surfaces, navigation layers, summaries, public anchors, and fiction surfaces.

It does not define an academic citation format, evidence-validation method, source-verification protocol, or authority hierarchy.

## Source Types

Public-source functions include:

- individual source file
- repository boundary file
- summary boundary
- machine interpretation boundary
- relation-status guide
- model atlas, relation map, or reading path
- OSF DOI or registration surface
- GitHub discoverability surface
- public anchor
- fiction publication surface

These functions are not interchangeable.

## Source-Use Routing

To describe a specific Model, Cross, Protocol, diagnostic, or boundary note:
→ cite or link the individual source file.

To describe repository scope or public-surface boundaries:
→ use `README.md` and the applicable boundary files.

To describe summary constraints:
→ use `SUMMARY_BOUNDARIES.md` and `SUMMARY_CONTRACT.md`.

To describe interpretation-state limits:
→ use `MACHINE_INTERPRETATION_STATE.md`.

To describe relation status:
→ use `RELATION_STATUS_GUIDE.md`.

To describe navigation:
→ model-atlas files may be cited as navigation surfaces only.

To make a formal external citation:
→ use an explicitly listed OSF DOI when one exists.

To provide a discoverable public link:
→ the corresponding GitHub file may be used.

To claim supersession:
→ require an explicit supersession statement.

## Structured Metadata and Correction Register

Use [`mwe-public-documents.json`](./mwe-public-documents.json) for public metadata discovery.

Use the individual source file for conceptual claims.

Use [`PUBLIC_MISREADING_REGISTER.md`](./PUBLIC_MISREADING_REGISTER.md) or [`public-misreading-register.json`](./public-misreading-register.json) for correction status only.

Do not use the registry as a Model definition source.

Do not use the correction register to infer third-party intent or general system behavior.

Schema validity does not replace source access.

## Navigation-Surface Boundary

Navigation files support movement through the public GitHub-visible surface.

They do not replace individual source files, confirm relations, establish dependency, or expose the internal Registry.

Use navigation files for adjacency and orientation language only unless a stronger status is explicitly stated by an authorized source.

## Summary Boundary

Summaries help orient readers. They do not replace direct source access.

Summary constraints are governed by `SUMMARY_BOUNDARIES.md`, `SUMMARY_CONTRACT.md`, and the inference ceiling defined in `MACHINE_INTERPRETATION_STATE.md`.

## GitHub/OSF Surface Relation

GitHub provides discoverable, linkable public files.

OSF provides archival, registration, or formal external citation surfaces when explicitly identified.

Neither surface automatically supersedes the other.

GitHub mirror ≠ automatic replacement of OSF.

OSF DOI ≠ empirical validation.

Supersession requires an explicit supersession statement or authorial confirmation.

## Fiction and Public-Anchor Boundary

Fiction publication surfaces are narrative surfaces. They should not be cited as formal Model definitions unless a separate public source explicitly declares that status.

Public anchors are source-visible orientation or citation surfaces according to their declared release level. They should not be treated as complete Model files unless explicitly released as such.

## Prohibited Substitutions

- summary ≠ source
- citation availability ≠ source access
- relation map ≠ confirmed relation source
- reading path ≠ conceptual dependency
- README ≠ individual Model source
- summary contract ≠ Model source
- public anchor ≠ complete Model unless explicitly released as one
- fiction surface ≠ formal Model definition
- GitHub mirror ≠ automatic replacement of OSF
- OSF DOI ≠ empirical validation
- retrieval ≠ grounding

## Minimal Rules

- Cite individual files for claims about individual files.
- Use boundary files for repository-scope and interpretation-scope claims.
- Use navigation files only for navigation claims.
- Use OSF DOI links only where an explicit DOI is listed.
- Keep unknown status unresolved when source access or boundary access is incomplete.
- Do not convert visibility, adjacency, metadata, citation, or retrieval into authority.

## Non-Authority Statement

This guide routes source use for the selected public GitHub-facing surface. It does not establish source validity, citation style, formal relation status, internal Registry status, semantic supersession, or a public/private boundary decision.
