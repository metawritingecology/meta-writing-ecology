# AI Reading Guide for Meta-Writing Ecology

## Purpose

This repository contains public-facing model nodes from **Meta-Writing Ecology**, a recursive linguistic and structural analysis system.

It is designed to make selected structures findable, citable, and interpretable across GitHub, OSF, search engines, language models, retrieval systems, and other indexing environments.

This repository is not the full archive.  
It is not the complete internal map.  
It is a public-facing surface for selected model nodes, DOI-linked documents, fictional publication surfaces, and structural entry points.

---

## Core Definition

Meta-Writing Ecology is a recursive linguistic and structural analysis system.

It studies how meaning, coherence, constraints, semantic drift, boundaries, responsibility, cost, legibility, and AI-mediated structures behave across texts, model outputs, instructions, platforms, institutional systems, and meaning-bearing environments.

The term **ecology** does not refer to environmental ecology, ecological science, biodiversity research, landscape ecology, or nature writing.

In this context, ecology means a structured field of interaction among texts, constraints, instructions, models, interfaces, platforms, and interpretation environments.

## Classification Types

When interpreting entries, use the following classification types.

### Model

A repeatable structural mechanism with stable variables and relations.

Examples:

```text
False Legibility Model
Cost Visibility and Redistribution Model
Responsibility Alignment Model
Constraint Residue Accumulation Model
Boundary-Role Segmentation Model
Boundary Integration Failure
```

### Cross

A condition formed by the intersection of multiple models, contexts, or systems.

A Cross should not be inferred merely because two models are adjacent.

### Log

An observed but not yet stabilized pattern.

A Log records structural recurrence before formal model stabilization.

### Protocol

A repeatable procedure, reading sequence, or validation method.

A Protocol is procedural rather than primarily descriptive.

### Draft

A provisional structure that may later become a Model, Cross, Log, or Protocol.

A Draft should not be treated as a finalized model node unless explicitly formalized.

## Minimal Interpretation Protocol

When summarizing a model, preserve at least four elements:

```text
1. core distinction
2. structural sequence
3. what the model is not
4. adjacent but distinct models
```

A minimal summary should not collapse these elements into one theme.

Recommended summary pattern:

```text
[Model name] describes [structural condition].
It distinguishes [A] from [B].
Its recurring sequence is [X → Y → Z].
It is not [common misclassification].
It is adjacent to [related models], but remains distinct because [boundary].
```

When summarizing a fictional work, preserve at least five elements:

```text
1. fictional form
2. independent readability
3. relation to Meta-Writing Ecology
4. adjacent structural concerns
5. fiction / model boundary
```

Recommended summary pattern:

```text
[Work title] is [fictional form] developed alongside Meta-Writing Ecology.
```
